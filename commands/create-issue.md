Publish a draft from `.docs/` to GitHub with full project integration.

Arguments:
- `<slug>` (required) - Filename in `.docs/` (without .md), supports fuzzy matching
- `--status` (optional) - Column: Backlog, Ready, In Progress, In Review (default: Backlog)
- `--assignee` (optional) - GitHub username(s), comma-separated (default: from .env)
- `--priority` (optional) - P0, P1, or P2 (default: none)
- `--dry-run` (optional) - Preview without creating (default: false)

Steps:
1. Check `gh auth status`. If not authenticated, output: "GitHub CLI not authenticated. Run: `gh auth login`" and stop.
2. Read `.claude/GITHUB.md` and find "## Project Configuration" section. If missing, output: "Project config missing. Run: `/github-details`" and stop.
3. Extract from `.claude/GITHUB.md`:
   - Project Owner
   - Project Number
   - Project Node ID
   - Status Field ID and option IDs
   - Priority Field ID and option IDs (if present)
4. Read default assignee from `.claude/GITHUB.md`:
   - Find "Default assignee:" line in the Team section
   - If not found, use current user: `gh api user --jq .login`
   - Use the Team table to resolve display names to GitHub usernames when `--assignee` uses a first name
5. Find draft file in `.docs/` using fuzzy matching:
   - First try exact match: `.docs/<slug>.md`
   - If not found, list all `.md` files in `.docs/`
   - Fuzzy match: "hybrid assessment" matches "hybrid-assessment-type.md"
   - Matching logic: slug words appear in filename in any order
   - If multiple matches, output: "Multiple drafts match '<slug>':" followed by numbered list, then ask user to clarify
   - If no match, output: "No draft found matching '<slug>'. Available drafts:" followed by list of `.docs/*.md` files
6. Read the matched draft file
7. Extract title from first H1 heading (remove leading `#` and trim)
8. Validate draft has required sections:
   - Summary
   - Tasks
   - Success Criteria
   - If missing any, output: "Draft is missing required sections: <list>. Please update the draft." and stop
9. Parse arguments:
   - `--status`: Map user input to option ID from `.claude/GITHUB.md` (case-insensitive match)
   - `--assignee`: Use provided value(s) or default from .env (step 4)
   - `--priority`: Map to option ID from `.claude/GITHUB.md` (case-insensitive match)
10. If `--dry-run` flag is set:
   - Output preview:
     ```
     Title: <title>
     Body: <first 200 chars>...
     Status: <status>
     Priority: <priority or "None">
     Assignee: <assignee>

     Preview only (--dry-run). Run without --dry-run to create.
     ```
   - Stop
11. Create issue via `gh issue create --title "<title>" --body-file <draft-path>`
12. Extract issue number from output (format: "https://github.com/.../issues/<number>")
13. Add issue to project: `gh project item-add <project-number> --owner <project-owner> --url <issue-url>`
14. If status is not "Backlog":
    - Run: `gh project item-edit --project-id <project-node-id> --id <item-id> --field-id <status-field-id> --single-select-option-id <status-option-id>`
    - Get item-id from step 13 output
15. If priority is specified:
    - Run: `gh project item-edit --project-id <project-node-id> --id <item-id> --field-id <priority-field-id> --single-select-option-id <priority-option-id>`
16. Assign users: `gh issue edit <issue-number> --add-assignee <assignee>`
17. Output success message:
    ```
    Created: <issue-url>
    Issue #<number> added to Project <project-number>
    Status: <status>
    Priority: <priority or "None">
    Assignee: <assignee>

    Run `/create-branch <number>` to create a linked branch.
    ```

Important:
- Do NOT add Claude signature or "Generated by Claude" footer to the issue
- The issue should appear human-written
- Use the draft markdown content as-is for the issue body

Error messages:
- "GitHub CLI not authenticated. Run: `gh auth login`"
- "Project config missing. Run: `/github-details`"
- "No draft found matching '<slug>'. Available drafts: ..."
- "Multiple drafts match '<slug>': ..."
- "Draft is missing required sections: ..."
- "Invalid status '<status>'. Valid options: Backlog, Ready, In Progress, In Review"
- "Invalid priority '<priority>'. Valid options: P0, P1, P2"

Example usage:
- `/create-issue hybrid assessment type`
- `/create-issue hybrid-assessment-type --status "In Progress" --priority P1`
- `/create-issue hybrid-assessment-type --assignee user1,user2 --dry-run`
